# UI Requirements

## Design Principle

Taurus should feel like hiring and managing employees, not configuring AI infrastructure.

## Core Screens

### 1. Landing Page

Purpose:
- explain Taurus simply,
- show the five-minute hiring promise,
- invite signup.

Hero:
> Hire AI employees in five minutes.

Subcopy:
> Taurus helps enterprises create, manage, and collaborate with AI employees using company knowledge.

### 2. Signup and Login

Requirements:
- email/password auth or auth provider integration,
- clean error states,
- secure redirect,
- enterprise trust copy.

### 3. Organization Onboarding

Fields:
- organization name,
- industry,
- website,
- company size,
- primary use case.

### 4. Dashboard

Sections:
- AI Employees
- Hire Employee CTA
- Knowledge Vault status
- Recent activity
- Usage summary
- Collaboration requests

Empty state:
> You have not hired any AI employees yet. Hire your first AI employee in five minutes.

### 5. Hiring Studio

Steps:
1. Choose role
2. Add knowledge
3. Define responsibilities
4. Choose tone
5. Review DNA
6. Hire employee

### 6. Employee Card

Shows:
- name,
- role,
- department,
- status,
- visibility,
- responsibilities,
- active DNA version,
- knowledge source count,
- usage,
- recent activity.

### 7. Knowledge Vault

Shows:
- uploaded files,
- source status,
- processing state,
- owner,
- employee association,
- last indexed date.

### 8. Chat Test Console

Shows:
- conversation,
- answer,
- citations,
- confidence signal,
- feedback buttons.

### 9. Collaboration Requests

Shows:
- requesting employee,
- responding employee,
- request,
- response,
- status,
- audit metadata.

### 10. Audit Log

Shows:
- timestamp,
- actor,
- action,
- target,
- summary.

### 11. Usage Dashboard

Shows:
- messages,
- employees,
- files,
- collaboration requests,
- token usage placeholder,
- storage placeholder.
